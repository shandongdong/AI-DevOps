## 五、技术选型说明

### 5.1 为什么沿用若依单体 + 多模块？

- 若依单体版（前后端同仓或相近）开箱即用，权限/菜单/字典/代码生成等基础设施完备，二次开发成本低。
- Maven 多模块分层清晰（common/framework/system/quartz/generator/admin），业务可独立成模块（ai-devops），与上游解耦，便于持续同步官方更新。

### 5.2 为什么 ai-devops 独立成模块？

- 把自有业务放进 `ai-devops/` 模块（上游没有此目录），上游更新永远不会冲突它；包名 `com.ruoyi.aidevops.*` 落在启动类默认扫描范围内，无需改启动类。
- 详见笔记 `02-业务模块开发` 的模块隔离实践。

### 5.3 为什么前端用 Vue3 + TypeScript 版？

- Vue3 + Composition API + `<script setup>` 更适合中大型业务，TS 类型安全降低维护成本。RuoYi-Vue3 的 `typescript` 分支提供完整的权限、菜单、字典适配，直接复用。

### 5.4 为什么用 JWT？

- 前后端分离场景下，无状态 token 便于水平扩展；若依用 JWT + Redis 双端管理（登录态缓存 + 强制下线），兼顾无状态与可控性。
