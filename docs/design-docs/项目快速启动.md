# 项目快速启动

> 从零搭建到联调的完整流程。GitFlow 分支与双 remote 协作详见外部笔记 `01-基于RuoYi-Vue二次开发与上游同步`，本文聚焦本地开发链路。

## 一、环境准备

### 1.1 安装开发工具

| 工具 | 版本 | 用途 |
|------|------|------|
| JDK | 17+ | 后端运行 |
| Maven | 3.8+ | 后端构建 |
| Node.js | 18+ | 前端运行（corepack 启用 yarn 1.22.x） |
| MySQL | 8.0 | 数据库 |
| Redis | 6+ | 缓存 |
| IDEA | — | 后端 IDE |

### 1.2 配置加速镜像

Maven（`settings.xml`）：

```xml
<mirror>
    <id>aliyun</id>
    <mirrorOf>central</mirrorOf>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

> 本项目根 `pom.xml` 已配置阿里云仓库，可不再单独设 settings。

## 二、获取代码（双 remote 协作）

```bash
# clone 自有私有仓库（已含若依后端 + 前端 zip）
git clone git@github.com:shandongdong/AI-DevOps.git
cd AI-DevOps

# 确认远程（origin=私有，upstream=若依官方只读）
git remote -v
# origin    git@github.com:shandongdong/AI-DevOps.git
# upstream  https://github.com/yangzongzhuan/RuoYi-Vue.git

# 切到 develop 开发主线
git switch develop
# 新功能从这里拉 feature 分支
git switch -c feature/ai-devops-xxx
```

## 三、初始化数据库

```sql
-- 创建数据库（字符集 utf8mb4）
CREATE DATABASE IF NOT EXISTS `ai-devops` CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

数据库脚本由 Flyway 迁移管理（位于 `ai-devops/src/main/resources/db/migration/`）：

1. `V1__ruoyi_base_tables.sql` —— 若依基础表（sys_user / sys_role / sys_menu / sys_dict 等）
2. `V2__quartz_tables.sql` —— 定时任务表（QRTZ_* + sys_job*）

> 启用 Flyway（`spring.flyway.enabled=true`）后，启动应用即自动迁移：已有库打 v2 基线跳过 V1/V2（已手动执行过），全新库则执行初始化。详见 `项目开发规范.md` 3.2。

## 四、配置后端项目

项目采用**环境自包含**的多环境配置（对齐源项目规范）：主 `application.yml` 只放跨环境公共项（端口、上传路径、token、MyBatis 等），**不含 Redis 和 Flyway**；这两项是环境差异项，由 `application-{env}.yml` 各自完整配置；数据源由 `application-druid-{env}.yml` 提供。本地默认激活 `dev,druid-dev`（主 yml 已配），开箱即用。

### 4.1 数据源 `application-druid-{env}.yml`

本地开发默认走 `application-druid-dev.yml`（主 yml `active: dev,druid-dev` 已激活）。改本环境的连接信息即可，无需动其他环境文件：

```yaml
spring:
    datasource:
        druid:
            master:
                url: jdbc:mysql://<你的MySQL>:3306/ai-devops?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
                username: ${DB_USERNAME:<账号>}        # 凭据走环境变量，默认值兜底
                password: ${DB_PASSWORD:<密码>}
```

### 4.2 Redis 与 Flyway `application-{env}.yml`

Redis 与 Flyway 按环境独立配置，不在主 `application.yml`。本地开发改 `application-dev.yml`：

```yaml
spring:
  data:
    redis:
      host: <你的Redis>
      port: 6379
      password: ${REDIS_PASSWORD:<Redis密码>}   # 凭据走环境变量，无密码则留空
  flyway:
    enabled: false                # 开发环境关闭（频繁改 SQL）；test/prod 开启
    locations: classpath:db/migration
```

> 三环境差异：dev/test 的 Redis 在 `192.168.130.41`、Flyway dev 关 / test 开；prod 的 Redis 在 `192.168.130.31`、Flyway 开。详见 [多环境部署文档](../deploy/多环境部署文档.md) §2。

### 4.3 日志与上传路径 `logback.xml` / `application.yml`

- `logback.xml` 的 `log.path`（默认 `./ruoyi/logs`）
- `application.yml` 的 `ruoyi.profile`（文件上传，默认 `./ruoyi/uploadPath`）

> ⚠️ 凭据勿提交真实生产值：dev 用 `${ENV_VAR:内网默认值}` 兜底（本地友好），**test/prod 用 `${ENV_VAR:changeme}` 占位符（库内零真实凭据，部署前必须 export 环境变量）**；也可用 `application-local.yml`（加 `.gitignore`）覆盖本地。详见 [多环境部署文档](../deploy/多环境部署文档.md) §2。

## 五、启动后端

### 5.1 IDE 启动

运行 `ruoyi-admin` 模块的 `com.ruoyi.RuoYiApplication`（需 JDK 17）。成功标志：

```
INFO  o.a.c.h.Http11NioProtocol - Starting ProtocolHandler ["http-nio-8080"]
INFO  c.r.RuoYiApplication - Started RuoYiApplication in X.X seconds
(♥◠‿◠)ﾉﾞ  若依启动成功   ლ(´ڡ`ლ)ﾞ
```

### 5.2 命令行打包启动

```bash
mvn clean package -DskipTests
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

后端默认端口 **8080**，`context-path: /`。

### 5.3 验证 ai-devops 模块

浏览器直接访问（无需登录，因带 `@Anonymous`）：

```
http://localhost:8080/aidevops/health
```

返回 `{"msg":"操作成功","code":200,"data":{"module":"ai-devops","status":"UP",...}}` 即模块创建成功。

## 六、启动前端

```bash
cd ruoyi-ui-vue3

# corepack 启用 yarn 1.22.x
corepack enable
corepack prepare yarn@1.22.22 --activate
yarn -v    # 应输出 1.22.x

# 安装依赖（npmmirror 加速）
yarn --registry=https://registry.npmmirror.com

# 启动开发服务
yarn dev
```

前端访问 `http://localhost:80`，devServer 代理已指向后端 8080，无需额外配置。

## 七、联调验证

1. 后端 8080 + 前端 `yarn dev`(80) 同时启动。
2. 浏览器访问 `http://localhost:80`，用默认账号 `admin / admin123` 登录。
3. 菜单与页面正常展示 → 环境搭建成功。
4. 可选关闭验证码：`sys_config` 表 `sys.account.captchaEnabled` 设为 `false`。

## 八、开发循环

```
develop 上拉 feature 分支
  → 写代码（后端 ai-devops 模块 / 前端 views+api）
  → mvn 编译 / yarn dev 自测
  → 同步更新 docs 对应文档
  → 提交（中文 + 前缀，不加 Co-Authored-By）
  → 合回 develop
```

## 九、同步上游更新（参考）

```bash
git fetch upstream
git switch master
git merge upstream/master     # 冲突①：仅若依自身变更
git push origin master

git switch develop
git merge master              # 冲突②：上游 vs 你的业务（模块隔离后极少）
git push origin develop
```

> 因 ai-devops 模块上游永不触碰，步骤 ② 的冲突集中在根 pom 等少量文件，详见 `项目开发规范` 的冲突处理原则。
