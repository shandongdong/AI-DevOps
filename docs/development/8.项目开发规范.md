# 项目开发规范

> 承接若依官方规范，结合本项目（ai-devops 自有模块、Flyway 迁移、GitFlow 双 remote 协作、Vue3 + TS）补充约束。本文档记录开发踩过的坑与最佳实践。

## 1. 后端开发规范

### 1.1 代码结构规范

#### 包结构规范

若依上游模块（ruoyi-system 等）沿用扁平四层：

```
com.ruoyi.system
├── controller      // 控制器层
├── service         // 服务接口层
│   └── impl       // 服务实现层
├── mapper          // 数据访问层
└── domain          // 实体类层
```

**注意**：`ai-devops` 模块中的业务代码按**功能域**分为子包管理。每个子包包含完整的 Controller / Service / Mapper / Domain / Util 分层：

```
com.ruoyi.aidevops
├── controller/
│   └── modulexxx/          # 功能域 A 的控制器
├── service/
│   └── modulexxx/          # 接口 + impl/
├── mapper/
│   └── modulexxx/
├── domain/
│   └── modulexxx/          # 含 vo/ 子目录（按需）
└── util/
    └── modulexxx/          # 功能域专属工具
```

新增业务模块时，在 `com.ruoyi.aidevops` 下按功能域新建子包（如 `com.ruoyi.aidevops.controller.modulexxx`），各层均放在对应子包下。前端代码对应放 `ruoyi-ui-vue3/src/views/ai-devops/modulexxx`。

> 这样按功能域聚合的好处：删除/迁移一个功能域时，各层文件集中在一起，不用跨目录翻找；比"按层聚合"（所有 Controller 堆一起）更适合多人协作与 LLM 生成。

#### 命名规范

**类命名**:

| 类型         | 规范                             | 示例                       |
| ---------- | ------------------------------ | ------------------------ |
| Controller | `XxxController`                | `SysUserController`      |
| Service 接口 | `IXxxService`                  | `ISysUserService`        |
| Service 实现 | `XxxServiceImpl`               | `SysUserServiceImpl`     |
| Mapper     | `XxxMapper`                    | `SysUserMapper`          |
| Entity     | `XxxEntity`（**必须以 Entity 结尾**） | `ProductModelListEntity` |

**方法命名**:

| 操作   | 规范                                 | 示例                |
| ---- | ---------------------------------- | ----------------- |
| 查询列表 | `selectXxxList`                    | `selectUserList`  |
| 查询单个 | `selectXxxById`                    | `selectUserById`  |
| 新增   | `insertXxx`                        | `insertUser`      |
| 修改   | `updateXxx`                        | `updateUser`      |
| 删除   | `deleteXxxById` / `deleteXxxByIds` | `deleteUserByIds` |

### 1.2 Controller 层规范

```java
@RestController
@RequestMapping("/aidevops/user")
public class UserController extends BaseController {

    @Autowired
    private IUserService userService;

    /**
     * 查询用户列表
     */
    @PreAuthorize("@ss.hasPermi('aidevops:user:list')")
    @GetMapping("/list")
    public TableDataInfo list(User user) {
        startPage();
        List<User> list = userService.selectUserList(user);
        return getDataTable(list);
    }

    /**
     * 新增用户
     */
    @PreAuthorize("@ss.hasPermi('aidevops:user:add')")
    @Log(title = "用户管理", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@Validated @RequestBody User user) {
        return toAjax(userService.insertUser(user));
    }
}
```

**规范要点**:

1. 继承 `BaseController`，使用通用方法（`startPage`/`getDataTable`/`toAjax`）
2. 权限控制用 `@PreAuthorize("@ss.hasPermi('aidevops:xxx:yyy')")`，权限标识以 `aidevops:` 为前缀
3. 操作日志用 `@Log` 注解
4. 参数校验用 `@Validated`
5. 方法需完整 JavaDoc 注释
6. RESTful 风格 URL：`/aidevops/{模块}/{操作}`

### 1.3 Service 层规范

**接口与实现分离**，实现类用 `@Transactional` 管理事务，复杂业务逻辑在 Service 层处理，Controller 只做参数接收与结果封装。

```java
public interface IUserService {
    List<User> selectUserList(User user);
    int insertUser(User user);
}

@Service
public class UserServiceImpl implements IUserService {
    @Autowired
    private UserMapper userMapper;

    @Override
    @Transactional
    public int insertUser(User user) {
        return userMapper.insertUser(user);
    }
}
```

### 1.4 Mapper 层规范

- 使用 `resultMap` 定义映射关系（不用 `resultType` 自动映射，字段多时易错）
- 用 `<sql>` 标签定义可复用 SQL 片段
- 用 `<if>` 实现动态 SQL
- 参数用 `#{}` 防注入，**禁止** **`${}`**（除非动态表名/列名且已校验）
- XML 文件名与 Mapper 接口名一致，放 `resources/mapper/aidevops/{modulexxx}/`

```xml
<select id="selectUserList" parameterType="User" resultMap="UserResult">
    <include refid="selectUserVo"/>
    <where>
        del_flag IN ('0')
        <if test="userName != null and userName != ''">
            AND user_name like concat('%', #{userName}, '%')
        </if>
    </where>
</select>
```

### 1.5 Entity 层规范

```java
public class UserEntity extends BaseEntity {
    private static final long serialVersionUID = 1L;

    /** 用户ID */
    @Excel(name = "用户序号", cellType = ColumnType.NUMERIC)
    @JsonSerialize(using = ToStringSerializer.class)   // ← Long 必加，见 1.9
    private Long userId;

    /** 用户账号 */
    @Excel(name = "登录名称")
    @NotBlank(message = "用户账号不能为空")
    @Size(min = 0, max = 30, message = "用户账号长度不能超过30个字符")
    private String userName;
    // getter/setter...
}
```

**规范要点**:

1. 继承 `BaseEntity`（含 `createBy`/`createTime`/`updateBy`/`updateTime`/`remark` 公共字段）
2. 实现 `Serializable`（`serialVersionUID`）
3. 用 JSR303 注解（`@NotBlank`/`@Size`/`@Email`）做参数校验
4. 用 `@Excel` 支持导入导出
5. 字段注释完整，说明含义与取值范围

### 1.6 异常与日志规范

- 业务异常抛 `ServiceException`（`ruoyi-common.exception`），由全局 `GlobalExceptionHandler` 兜底转 `AjaxResult.error`，**不抛裸** **`RuntimeException`**
- 日志用 `@Slf4j` 或 `LoggerFactory.getLogger(Xxx.class)`，类名作 logger；调试用 `log.debug`，禁 `System.out.println`
- 关键操作用 `@Log` 注解记录到操作日志表；日志路径由 `logback.xml` 的 `log.path` 控制（本项目 `./ruoyi/logs`）

### 1.7 注解使用约定

| 注解                | 来源                        | 用途                                                |
| ----------------- | ------------------------- | ------------------------------------------------- |
| `@RestController` | Spring                    | 返回 JSON                                           |
| `@Anonymous`      | `ruoyi-common.annotation` | 匿名访问（白名单），**加白名单必须用此注解，禁止改** **`SecurityConfig`** |
| `@PreAuthorize`   | Spring Security           | 权限控制，如 `@ss.hasPermi('aidevops:user:list')`       |
| `@Log`            | `ruoyi-common.annotation` | 操作日志记录（标在 Controller 方法）                          |
| `@DataScope`      | 同上                        | 部门数据权限                                            |
| `@DataSource`     | 同上                        | 主从数据源切换                                           |

> 白名单机制：`PermitAllUrlProperties`（ruoyi-framework）启动时扫描所有 `@Anonymous` 方法/类，自动把路径加入 Security 放行列表。

### 1.8 ai-devops 模块新增规范

- 新增 Controller 放 `com.ruoyi.aidevops.controller.{modulexxx}`，包名必须在 `com.ruoyi.*` 下（启动类 `com.ruoyi.RuoYiApplication` 默认扫描范围，无需改启动类）
- 新增 Mapper/Domain 放 `com.ruoyi.aidevops.*`，Mapper XML 放 `resources/mapper/aidevops/{modulexxx}/`
- **禁止改上游模块**（ruoyi-system 等）实现自有业务；如需复用，通过依赖 `ruoyi-common` 或引用 `ruoyi-system`

### 1.9 常见踩坑记录

#### 软删除（必须遵守）

本项目**永远不物理删除数据**。删除操作实际是更新 `del_flag` 字段：

```java
// ✅ 正确：逻辑删除
public int deleteXxxById(Long xxxId) {
    XxxEntity entity = new XxxEntity();
    entity.setXxxId(xxxId);
    entity.setDelFlag("2");
    entity.setUpdateBy(SecurityUtils.getUsername());
    entity.setUpdateTime(DateUtils.getNowDate());
    return xxxMapper.updateXxx(entity);
}
```

```xml
<!-- ✅ 正确：查询时必须过滤已删除数据，用 IN 不用 = -->
<select id="selectXxxList" resultMap="XxxResult">
    select * from ai_devops_xxx
    <where>
        del_flag IN ('0')
        <if test="xxxName != null and xxxName != ''">
            AND xxx_name like concat('%', #{xxxName}, '%')
        </if>
    </where>
</select>
```

**要点**：

- 删除时设 `del_flag = '2'`，同时更新 `update_by` 和 `update_time`
- 所有查询必须含 `del_flag IN ('0')`（用 `IN` 不用 `=`，方便后续扩展多状态）

#### Long 类型精度丢失（必须遵守）

JavaScript Number 最大安全整数 `2^53 - 1`（约 16 位），Java Long 最大 `2^63 - 1`（19 位）。超 16 位 Long 传前端会丢精度。

```java
// ✅ 正确：Long 字段加序列化注解
@JsonSerialize(using = ToStringSerializer.class)
private Long xxxId;
```

```java
import com.fasterxml.jackson.databind.annotation.JsonSerialize;
import com.fasterxml.jackson.databind.ser.std.ToStringSerializer;
```

**规则**：实体类所有 `Long` 类型字段必须加 `@JsonSerialize(using = ToStringSerializer.class)`。

#### AjaxResult 返回 String 的陷阱

`AjaxResult` 有两个 `success` 重载：

- `success(String msg)` → 数据放入 `msg` 字段
- `success(Object data)` → 数据放入 `data` 字段

业务返回 String 且前端从 `response.data` 取值时，会匹配到 `success(String msg)`，前端取不到数据：

```java
// ❌ 错误：String 匹配到 success(String msg)，前端 response.data 为 null
@GetMapping("/generateCode")
public AjaxResult generateCode() {
    String code = xxxService.generateCode();
    return success(code);
}

// ✅ 正确：强转 Object，匹配 success(Object data)
@GetMapping("/generateCode")
public AjaxResult generateCode() {
    String code = xxxService.generateCode();
    return success((Object) code);
}
```

#### 实体类命名（必须遵守）

所有业务实体类必须以 `Entity` 结尾：

```java
// ✅ 正确
public class ProductModelListEntity extends BaseEntity { }

// ❌ 错误
public class ProductModel extends BaseEntity { }
```

### 2.3 Vue 组件规范

用 `<script setup lang="ts" name="Xxx">` + Composition API，不用 Options API：

```vue
<script setup lang="ts" name="User">
import { listUser, delUser } from "@/api/ai-devops/user"
import type { User, UserQueryParams } from '@/types/api/ai-devops/user'

const { proxy } = getCurrentInstance()
const router = useRouter()
const { sys_normal_disable } = useDict("sys_normal_disable")

const loading = ref(true)
const total = ref(0)
const userList = ref<User[]>([])
const showSearch = ref(true)
const ids = ref<number[]>([])
const open = ref(false)
const queryParams = reactive<UserQueryParams>({
    pageNum: 1,
    pageSize: 10,
    userName: undefined,
    status: undefined
})

/** 查询用户列表 */
const getList = () => {
    loading.value = true
    listUser(queryParams).then(res => {
        userList.value = res.rows
        total.value = res.total
        loading.value = false
    })
}

/** 删除按钮操作 */
const handleDelete = (row: User) => {
    proxy.$modal.confirm('是否确认删除？').then(() => delUser(row.userId))
        .then(() => { getList(); proxy.$modal.msgSuccess("删除成功") })
        .catch(() => {})
}

onMounted(() => getList())
</script>
```

**规范要点**:

1. 组件用 `<script setup lang="ts" name="Xxx">`，`name` 用于 keep-alive 缓存
2. 接口请求统一走 `@/utils/request`（axios 封装，自动带 token、统一错误处理）
3. 权限按钮用 `v-hasPermi="['aidevops:user:add']"` 指令
4. 字典标签用 `<dict-tag>`
5. 通用组件（分页、工具栏等）复用 `@/components`
6. 样式用 `<style scoped lang="scss">` 避免污染

### 2.4 API 接口规范

统一走 `@/utils/request` 封装，方法命名规范（list/get/add/update/del）：

```typescript
import request from '@/utils/request'

// 查询用户列表
export function listUser(query: UserQueryParams) {
    return request({ url: '/aidevops/user/list', method: 'get', params: query })
}
// 新增用户
export function addUser(data: User) {
    return request({ url: '/aidevops/user', method: 'post', data })
}
```

GET 用 `params`，POST/PUT 用 `data`。

### 2.5 路由规范

### 2.7 常见踩坑记录

#### 隐藏子页面路由与面包屑

form/detail 等不在菜单中的页面需要三处配置，缺一不可：

1. **`router/index.ts`** **注册静态路由**（用 `createBreadcrumbRoute`，parentPath 带 `/aidevops`）
2. **`Breadcrumb/index.vue`** **添加特殊处理**：找到一级目录 + 列表页路由，展开并设 `path`，否则面包屑不可点击
3. **跳转路径规则**：
   - 列表→子页面：`/aidevops/{模块}/{子页面}`（如 `/aidevops/user/form`）
   - 子页面→返回列表：`/{菜单路径}`（如 `/user`，不带 `/aidevops`，因列表页是数据库动态路由）

**常见错误**：

- 忘记在 Breadcrumb 添加特殊处理 → 面包屑断层
- `matched.push(listRoute)` 没展开设 `path` → 面包屑不可点击
- 子页面返回路径写成 `/aidevops/xxx` → 404

> 具体代码结构参考老项目 `RuoYi-Vue` 的 `src/router/index.ts` 与 `Breadcrumb/index.vue`，按 Vue3 语法改写。

#### 权限

- 新增按钮/操作时，**必须**生成对应的权限菜单 SQL（`sys_menu` 类型 F）
- **隐藏子页面（form/detail）不需要在 sys\_menu 插记录**：路由由前端 `router/index.ts` 静态注册，访问权限由列表页按钮权限（`v-hasPermi`）统一控制。若误插隐藏菜单，会导致角色配置页出现多余勾选项。

## 3. 数据库设计规范

### 3.1 表设计规范

1. **表名**：小写，下划线分隔。ai-devops 业务表以 `ai_devops_` 开头（如 `ai_devops_product_model`），与若依 `sys_`/`gen_` 区分；Java 类名不加 AiDev 前缀
2. **字段名**：小写，下划线分隔，如 `user_name`
3. **主键**：用 `{表名简写}_id`（自增），**不用裸** **`id`**，类型 `bigint`
4. **必须字段**：`{表名简写}_name`、`status`（char(1)，0=正常，1=停用）、`del_flag`（char(1)，0=存在，2=删除）、`remark`
5. **BaseEntity 字段**（所有表必须）：
   - `create_by` varchar(64) 创建者
   - `create_time` datetime 创建时间
   - `update_by` varchar(64) 更新者
   - `update_time` datetime 更新时间
   - `remark` varchar(500) 备注
6. **无外键约束**：数据库层面不做外键，由代码层面控制关联关系
7. **空间换效率**：表设计优先查询效率，适当冗余
8. **SQL 注释规范**：CREATE TABLE 语句中字段注释之间**不能有空行**，否则 SQL 执行可能出错

### 3.2 数据库迁移（Flyway）

所有数据库表结构变更通过 Flyway 管理（含若依基础表与 ai-devops 业务表）。迁移文件路径：

```
ai-devops/src/main/resources/db/migration/
```

**命名格式**：`V{N}__description.sql`（注意是**两个下划线**）

```
V1__ruoyi_base_tables.sql        # 若依基础表（sys_*/gen_*，原 ry_20260417.sql）
V2__quartz_tables.sql            # 定时任务表（QRTZ_*，原 quartz.sql）
V3__create_ai_devops_health.sql     # ai-devops 业务表从 V3 起编号
```

> **V1/V2 已占用**：若依基础表与 quartz 表已纳入 Flyway 统一管理。项目启用 Flyway 前，这两个脚本已在开发/测试/生产库**手动执行过**，故 `FlywayConfig` 设 `baselineVersion("2")`：已有库会打 v2 基线并跳过 V1/V2（不重跑、不覆盖数据）；全新空库则 V1/V2 正常执行完成初始化。**ai-devops 业务表迁移从 V3 起编号**，新库旧库都会应用。Flyway 是唯一执行入口，不保留独立 sql/ 目录。

**注意事项**：

- 已执行的迁移文件不能修改（Flyway 校验 checksum）
- 版本号必须递增
- 描述用英文下划线分隔

#### Flyway 配置（若依动态数据源坑）

**背景**：两重原因使 Flyway 必须手动配置：
1. 若依用了 Druid 动态数据源，并在启动类 `@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)` 排除了自动配置；
2. **Spring Boot 4.1.0 已移除 `FlywayAutoConfiguration` / `FlywayProperties`**（3.5.x 仍有，4.1.0 的 `spring-boot-autoconfigure` 与 `spring-boot-sql` jar 中均无 Flyway 类）。因此 `application.yml` 里的 `spring.flyway.*` 没有框架自动绑定，只由本配置类的 `@ConditionalOnProperty` / `@Value` 读取生效。

故须手动绑定主数据源，在 `masterDataSource` 创建后执行迁移。

在 `ai-devops` 模块新建 `com.ruoyi.aidevops.config.FlywayConfig`：

```java
@Configuration
@ConditionalOnProperty(prefix = "spring.flyway", name = "enabled", havingValue = "true", matchIfMissing = false)
public class FlywayConfig {
    private static final Logger log = LoggerFactory.getLogger(FlywayConfig.class);

    @Bean
    // @Bean 参数注入 masterDataSource 已保证其在 flyway 之前创建，无需 @DependsOn
    public Flyway flyway(@Qualifier("masterDataSource") DataSource masterDataSource,
                         @Value("${spring.flyway.locations:classpath:db/migration}") String locations) {
        Flyway flyway = Flyway.configure()
                .dataSource(masterDataSource)
                .locations(locations)                 // 由 application.yml 覆盖，支持 profile 切换
                .encoding("UTF-8")
                .validateOnMigrate(true)
                .baselineOnMigrate(true)              // 支持已有库的环境
                // baselineVersion=2：V1(若依基础表)/V2(quartz 表) 启用 Flyway 前已手动执行过；
                //   已有库 → 在 v2 打基线，V1/V2 跳过不重跑（避免覆盖数据）；空库 → V1/V2 正常执行初始化。
                //   后续 ai-devops 业务表从 V3 起编号，新库旧库都会应用。
                .baselineVersion("2")
                .validateMigrationNaming(true)
                .load();
        // 不无条件 repair()：新库无历史可修，且会清除失败迁移记录、掩盖问题；
        // checksum 不一致由 validateOnMigrate 在 migrate 时直接抛出，让启动失败以提示运维。
        log.info("Flyway 迁移开始，locations={}, 数据源={}", locations, masterDataSource);
        flyway.migrate();   // 必须在 Bean 创建时执行，早于其他 Bean
        log.info("Flyway 迁移完成");
        return flyway;
    }
}
```

> **cleanDisabled 留默认值**：Flyway 12+ 默认 `cleanDisabled=true`，禁用破坏性 `clean()`（会 DROP 整个 schema 的表），**不要**手动设 `cleanDisabled(false)`，防止误清生产库。

依赖（`ai-devops/pom.xml` 加，版本由 Spring Boot BOM 管理）：

```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-mysql</artifactId>
</dependency>
```

`application.yml` 开关：

```yaml
spring:
  flyway:
    enabled: true          # 生产/测试开，本地按需
    locations: classpath:db/migration
```

> 参考实现：老项目 `RuoYi-Vue/devops-platform/.../config/FlywayConfig.java`（同动态数据源场景，配置可直接借鉴）。
>

### 3.3 索引规范

1. 主键自动创建唯一索引
2. 频繁查询字段建索引
3. 关联字段建索引
4. 索引命名：`idx_字段名` 或 `idx_字段1_字段2`

### 3.4 字段类型选择

| 数据类型       | 推荐场景            |
| ---------- | --------------- |
| `tinyint`  | 0-255 小整数，如状态标识 |
| `int`      | 一般整数            |
| `bigint`   | 大整数，如主键 ID      |
| `varchar`  | 变长字符串           |
| `char`     | 固定长度，如状态码       |
| `text`     | 长文本             |
| `datetime` | 日期时间            |
| `decimal`  | 精确小数，如金额        |

### 3.5 SQL 编写规范

1. 关键字小写
2. 避免 `select *`
3. 参数化查询防注入
4. 复杂查询加注释
5. 索引字段不使用函数

## 4. Git 使用规范

### 4.1 分支管理（GitFlow + 双 remote 协作）

| 分支                        | 职责                                 |
| ------------------------- | ---------------------------------- |
| `master`                  | 生产基线，只同步上游 + 接收 develop 合并，发版打 tag |
| `develop`                 | 开发集成，所有 feature 合入，可随时 merge 上游    |
| `feature/<number>-<slug>` | 单功能开发                              |
| `release/*`               | 发版准备                               |
| `hotfix/*`                | 生产紧急修复                             |

远程模型：`origin` = 私有仓库（AI-DevOps），`upstream` = 若依官方（RuoYi-Vue，只读同步）。

### 4.2 提交信息规范

前缀：`feat:`（新功能）/ `fix:`（修复）/ `docs:`（文档）/ `chore:`（杂项配置）/ `refactor:`（重构），用中文描述：

```
feat: 新建 ai-devops 业务模块与健康检查接口
```

- **不加** **`Co-Authored-By`** **签名行**

### 4.3 安全规范

- 数据源、Redis 等连接信息含真实凭据时谨慎提交；理想做法用本地 `application-local.yml`（加 `.gitignore`）或环境变量覆盖，库内 yml 保留示例值
- 明文密码进 git 历史无法彻底删除（需改写历史），发生泄露应**换密码 + 后续用环境变量管理**
