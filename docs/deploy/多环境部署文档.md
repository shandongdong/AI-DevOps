## 二、多环境配置说明

### 2.1 后端配置文件结构

项目采用 Spring Boot 的 Profile 机制实现多环境配置。dev/test/prod 三环境齐全：

```
ruoyi-admin/src/main/resources/
├── application.yml                    # 主配置（真公共项：端口/上传/token/MyBatis 等，不含 Redis/Flyway）
├── application-dev.yml                # 开发环境差异（Flyway 关、debug 日志）
├── application-druid-dev.yml          # 开发环境数据源（192.168.130.41/ai-devops）
├── application-test.yml               # 测试环境差异（Flyway 开、info 日志）
├── application-druid-test.yml         # 测试环境数据源（192.168.130.41/ai-devops，当前与 dev 同库）
├── application-prod.yml               # 生产环境差异（Redis 走 .31、Flyway 开、info 日志）
└── application-druid-prod.yml         # 生产数据源（192.168.130.30/ai-devops）
```

> 多环境采用**环境自包含法**（对齐源项目规范）：主 `application.yml` 只放真正的跨环境公共项（端口、上传路径、token、MyBatis、xss 等），**不含 Redis 和 Flyway**——这两项是环境差异项（各环境 Redis 地址/密码、Flyway 开关都不同），由 `application-{env}.yml` 各自完整配置；`application-druid-{env}.yml` 放各环境数据源。本地即开即用（主 yml `active: dev,druid-dev`）。
>
> **凭据策略**：dev 用 `${ENV_VAR:真实默认值}` 兜底（本地友好，默认值为内网开发库密码）；**test/prod 用 `${ENV_VAR:changeme}` 占位符，库内零真实凭据，部署前必须 export 环境变量**（`DB_PASSWORD`/`REDIS_PASSWORD`/`DB_USERNAME`/`DRUID_USERNAME`/`DRUID_PASSWORD`），未设则连接失败。IP 非凭据，保留明文。
>
> 注：上游若依原始 `application-druid.yml`（单数、明文数据源）已删除，对齐源项目规范——本地默认走 `application-druid-dev.yml`（凭据环境变量化），更贴合凭据治理。

### 2.2 当前配置文件说明

#### application.yml（主配置，公共）

- 公共配置：项目信息、端口 8080、上传路径、token、MyBatis、PageHelper、Springdoc、xss、referer 等**跨环境公共项**
- **不含 Redis 和 Flyway**（这两项是环境差异项，放各 `application-{env}.yml`）
- 默认激活环境：`dev,druid-dev`（本地开发，加载 dev 业务配置 + druid-dev 数据源）
- 通过启动参数 `--spring.profiles.active` 动态切换环境

#### application-dev.yml + application-druid-dev.yml（开发环境）

- `application-dev.yml`：**Redis（192.168.130.41，密码 `${REDIS_PASSWORD:DevOps#1024}` 兜底）+ Flyway 关闭**（开发频繁改 SQL）+ debug 日志
- `application-druid-dev.yml`：数据源 192.168.130.41/ai-devops，密码 `${DB_PASSWORD:DevOps#1024}` 兜底
- 启动：`--spring.profiles.active=dev,druid-dev`（默认，可不指定）

#### application-test.yml + application-druid-test.yml（测试环境）

- `application-test.yml`：**Redis（192.168.130.41，密码 `${REDIS_PASSWORD:changeme}` 占位符，部署前 export 环境变量）+ Flyway 开启**（测试库版本一致）+ info 日志
- `application-druid-test.yml`：数据源 192.168.130.41/ai-devops（当前与 dev 同库），密码 `${DB_PASSWORD:changeme}` 占位符，Druid 控制台账号 `${DRUID_USERNAME:changeme}` / `${DRUID_PASSWORD:changeme}`
- 启动：`--spring.profiles.active=test,druid-test`（`ry.sh start test` 内置）

#### application-prod.yml + application-druid-prod.yml（生产环境）

- `application-prod.yml`：**Redis 走 192.168.130.31**（密码 `${REDIS_PASSWORD:changeme}` 占位符，部署前必须 export 环境变量）+ **Flyway 开启** + info 日志
- `application-druid-prod.yml`：数据源 192.168.130.30/ai-devops（与 dev/test 的 .41 物理隔离），密码 `${DB_PASSWORD:changeme}` 占位符，Druid 控制台账号 `${DRUID_USERNAME:changeme}` / `${DRUID_PASSWORD:changeme}`
- 启动：`--spring.profiles.active=prod,druid-prod`（`ry.sh start prod` 内置）

### 2.3 环境切换原理

Spring Boot 通过 `spring.profiles.active` 激活对应 Profile。本项目用**双 profile**（业务配置 + 数据源分离）：

- **本地默认**：`active: dev,druid-dev`（主 yml + application-dev.yml + application-druid-dev.yml）
- **开发环境**: `dev,druid-dev`
- **测试环境**: `test,druid-test`
- **生产环境**: `prod,druid-prod`

> 凭据（DB 账号/密码、Redis 密码、Druid 控制台账号/密码）按 constitution 不入库明文：dev 用 `${ENV_VAR:真实默认值}` 兜底（本地友好），**test/prod 用 `${ENV_VAR:changeme}` 占位符，部署前必须 export 环境变量**（`DB_PASSWORD`/`REDIS_PASSWORD` 等）。也可用 `application-local.yml`（加 `.gitignore`）覆盖。

## 四、生产环境部署

### 4.1 生产架构

| 机器 | 角色 | 说明 |
|------|------|------|
| 192.168.130.32 | Nginx + 前端 | Nginx 主配置、ruoyi-prod.conf、前端静态资源 |
| 192.168.130.36 | 后端 1 | ruoyi-admin.jar（主节点） |
| 192.168.130.34 | 后端 2 | ruoyi-admin.jar（backup） |

- 用户访问 `http://192.168.130.32`，`/prod-api/` 由 Nginx 转发到 upstream `web_server`（36、34）
- Nginx 主配置定义 `upstream web_server`，ruoyi-prod.conf 中 `proxy_pass http://web_server/`

### 4.2 一键自动部署（推荐）

```bash
bash deploy_to_prod.sh
```

脚本执行步骤：
1. 上传 `docs/deploy/nginx/nginx.conf` 到 192.168.130.32 并替换 `/etc/nginx/nginx.conf`
2. 上传 `docs/deploy/nginx/ruoyi-prod.conf` 到 `/etc/nginx/conf.d/`，`nginx -t` 与 `reload`
3. 构建前端（`yarn build:prod`）并上传到 192.168.130.32 的 `/usr/share/nginx/html/ruoyi-ui/`
4. 构建后端，滚动部署到 192.168.130.36、192.168.130.34（上传 jar + ry.sh，分别 `restart prod`），分别打印两台结果

部署日志保存在 `logs/deploy_prod_YYYYMMDD_HHMMSS.log`。

**前置条件**：
- 本地已安装 Node.js、Yarn、Maven
- SSH 免密登录到 192.168.130.32、192.168.130.36、192.168.130.34
- 192.168.130.32 已装 Nginx；192.168.130.36、192.168.130.34 已装 Java 17

### 4.3 手动部署

#### 后端（36、34 各一份）


#### 前端（32）

## 六、前端环境变量说明

### 6.1 环境变量文件

前端用 Vite 的环境变量机制，配置文件位于 `ruoyi-ui-vue3/`：

- `.env.development` - 开发环境
- `.env.staging` - 测试环境
- `.env.production` - 生产环境

> 与老项目 Vue CLI（`VUE_APP_*`）不同，Vite 用 `VITE_*` 前缀，`import.meta.env.VITE_*` 读取。

### 6.2 环境变量说明

| 变量 | 开发 | 测试 | 生产 | 作用 |
|------|------|------|------|------|
| `VITE_APP_TITLE` | 页面标题 | 页面标题 | 页面标题 | 浏览器标题 |
| `VITE_APP_ENV` | development | staging | production | 环境标识 |
| `VITE_APP_BASE_API` | `/dev-api` | `/stage-api` | `/prod-api` | API 基础路径 |

### 6.3 `VITE_APP_BASE_API` 的作用

- **开发**: `/dev-api` → Vite devServer proxy 转发到 `http://localhost:8080`
- **测试**: `/stage-api` → Nginx 转发到后端
- **生产**: `/prod-api` → Nginx 负载均衡到 36、34

### 6.4 前端构建命令

```bash
cd ruoyi-ui-vue3
yarn dev            # 开发服务器（.env.development）
yarn build:stage    # 测试构建（.env.staging）
yarn build:prod     # 生产构建（.env.production）
```

> 依赖安装：`yarn --registry=https://registry.npmmirror.com`（本项目用 yarn，非 npm）

### 6.5 开发环境代理（vite.config.ts）

```typescript
server: {
  proxy: {
    '/dev-api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
      rewrite: (p) => p.replace(/^\/dev-api/, '')
    }
  }
}
```

前端请求 `/dev-api/system/user/list` → 转发到 `http://localhost:8080/system/user/list`。

## 七、Nginx 配置说明

### 7.1 配置文件位置

`docs/deploy/nginx/`：

- `nginx.conf` - 生产主配置（含 upstream 负载均衡）
- `ruoyi-prod.conf` - 生产站点配置（前端静态 + `/prod-api/` 代理到 web_server）
- `ruoyi-staging.conf` - 测试站点配置（前端静态 + `/stage-api/` 代理到 127.0.0.1:8080）

### 7.2 配置要点

#### 前端静态文件

```nginx
root   /usr/share/nginx/html/ruoyi-ui;
index  index.html index.htm;

location / {
    try_files $uri $uri/ /index.html;   # SPA 前端路由回退
    add_header Cache-Control "no-cache, no-store, must-revalidate";
}
```

#### API 代理

**生产**（`/prod-api/`，负载均衡）：

```nginx
location /prod-api/ {
    proxy_pass http://web_server/;   # 末尾 / 去掉前缀
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # WebSocket + 超时略
}
```

**测试**（`/stage-api/`，单机）：

```nginx
location /stage-api/ {
    proxy_pass http://127.0.0.1:8080/;
    # ...同上
}
```

#### context-path 说明

后端 `context-path: /`（根路径），**不按环境区分**。路径前缀（`/dev-api`/`/stage-api`/`/prod-api`）由前端代理或 Nginx 处理，后端始终接收去掉前缀后的路径（如 `/system/user/list`）。

### 7.3 外部回调路径（Webhook/OAuth）

新增非前端发起的外部回调路径（Webhook、OAuth）时，必须在 Nginx 配置加对应 `location` 代理规则（参考老项目曾有的 `/devops/repository/codereview/webhook/` 模式）。本项目当前无此类业务，按需新增。

### 7.4 部署 Nginx 配置

```bash
# 生产（32）
scp docs/deploy/nginx/nginx.conf root@192.168.130.32:/etc/nginx/nginx.conf
scp docs/deploy/nginx/ruoyi-prod.conf root@192.168.130.32:/etc/nginx/conf.d/
ssh root@192.168.130.32 'nginx -t && nginx -s reload'

# 测试（41）
scp docs/deploy/nginx/ruoyi-staging.conf root@192.168.130.41:/etc/nginx/conf.d/
ssh root@192.168.130.41 'nginx -t && nginx -s reload'
```

## 八、常见问题

### 8.1 如何切换环境？

**后端**：改启动参数 `--spring.profiles.active`，或 `./ry.sh start prod`。
**前端**：`yarn dev`（开发）/ `yarn build:stage`（测试）/ `yarn build:prod`（生产）。

### 8.2 如何确认当前环境？

启动日志显示 `The following profiles are active: ...`。

### 8.3 数据库连接失败？

1. 确认 MySQL 服务启动
2. 确认 IP/端口/库名（`ai-devops`）
3. 确认凭据（环境变量/`application-local.yml`）
4. 确认防火墙
5. 确认激活的 profile 对应的配置

### 8.4 前端 API 请求 404？

- 开发：检查 `vite.config.ts` proxy 与后端 8080 端口
- 测试：`yarn build:stage` 构建 + Nginx `/stage-api/` 代理
- 生产：Nginx `proxy_pass` 与后端服务、`/var/log/nginx/ruoyi-error.log`

### 8.5 生产如何更新配置？

1. 改对应 yml（如 `application-prod.yml`）
2. `mvn clean package -DskipTests`
3. 上传 jar
4. `./ry.sh restart prod`

### 8.6 如何加新环境？

1. 新建 `application-{env}.yml` + `application-druid-{env}.yml`
2. 启动指定 `--spring.profiles.active={env},druid-{env}`
3. 若要用 `ry.sh` 启动，需在 ry.sh 的环境分支里加 `{env}` 映射（当前内置 test/prod）
