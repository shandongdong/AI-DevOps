# 快捷备份步骤

**目录说明**：测试环境与生产环境使用不同脚本和备份子目录，互不覆盖。
- 测试环境：`database_backup_to_test.sh` → `/root/backups/mysql_backups/test`
- 生产环境：`database_backup_to_prod.sh` → `/root/backups/mysql_backups/prod`

1. 拷贝脚本到服务器（按环境上传到对应服务器）：
   - 测试环境（192.168.130.41）：`scp docs/deploy/database_backup_to_test.sh root@192.168.130.41:/root`
   - 生产环境（192.168.130.30）：`scp docs/deploy/database_backup_to_prod.sh root@192.168.130.30:/root`
2. 设置脚本权限：测试 `ssh root@192.168.130.41 'chmod +x /root/database_backup_to_test.sh'`，生产 `ssh root@192.168.130.30 'chmod +x /root/database_backup_to_prod.sh'`
3. **配置密码（必须）**：脚本不内嵌明文密码，执行前设置环境变量：
   ```bash
   # 在服务器上配置（测试 192.168.130.41 / 生产 192.168.130.30）
   export MYSQL_PASSWORD='你的密码'   # 或写入 ~/.bashrc 持久化，注意 chmod 600
   ```
4. 测试脚本（带密码环境变量）：测试 `ssh root@192.168.130.41 'MYSQL_PASSWORD=xxx bash /root/database_backup_to_test.sh'`，生产 `ssh root@192.168.130.30 'MYSQL_PASSWORD=xxx bash /root/database_backup_to_prod.sh'`
5. 查看备份目录：测试 `ssh root@192.168.130.41 'ls -lh /root/backups/mysql_backups/test/'`，生产 `ssh root@192.168.130.30 'ls -lh /root/backups/mysql_backups/prod/'`
6. 查看错误日志（如有）：测试 `ssh root@192.168.130.41 'ls -lh /root/backups/mysql_backups/test/*.err'`，生产 `ssh root@192.168.130.30 'ls -lh /root/backups/mysql_backups/prod/*.err'`
7. 追加定时任务（每天 2 点，在对应服务器配置；密码写进 crontab 环境变量或 `~/.my.cnf`）：
   - 测试：`ssh root@192.168.130.41 '(crontab -l 2>/dev/null; echo "MYSQL_PASSWORD=你的密码"; echo "0 2 * * * /bin/bash /root/database_backup_to_test.sh >> /root/backups/mysql_backups/test/backup.log 2>&1") | crontab -'`
   - 生产：`ssh root@192.168.130.30 '(crontab -l 2>/dev/null; echo "MYSQL_PASSWORD=你的密码"; echo "0 2 * * * /bin/bash /root/database_backup_to_prod.sh >> /root/backups/mysql_backups/prod/backup.log 2>&1") | crontab -'`
   > 更安全的做法：用 `~/.my.cnf`（`chmod 600`）存密码，脚本改用 `--defaults-extra-file` 读取，不在 crontab 暴露。见第八节安全建议。
8. 重启定时任务：测试 `ssh root@192.168.130.41 'systemctl restart cron'`，生产 `ssh root@192.168.130.30 'systemctl restart cron'`
9. 验证定时任务：`ssh root@192.168.130.41 'crontab -l'` 或 `ssh root@192.168.130.30 'crontab -l'`
10. 检查备份文件：测试 `ssh root@192.168.130.41 'ls -lt /root/backups/mysql_backups/test/*.sql | head -5'`，生产 `ssh root@192.168.130.30 'ls -lt /root/backups/mysql_backups/prod/*.sql | head -5'`
11. 查看执行日志：测试 `ssh root@192.168.130.41 'tail -20 /root/backups/mysql_backups/test/backup.log'`，生产 `ssh root@192.168.130.30 'tail -20 /root/backups/mysql_backups/prod/backup.log'`

## 一、脚本简介

项目提供两个备份脚本，按环境区分，避免测试与生产备份互相覆盖：

| 脚本 | 适用环境 | 默认备份目录 |
|------|----------|--------------|
| `database_backup_to_test.sh` | 测试环境 | `/root/backups/mysql_backups/test` |
| `database_backup_to_prod.sh`  | 生产环境 | `/root/backups/mysql_backups/prod`  |

两个脚本均支持全库备份、自动清理旧备份、错误日志记录；仅默认备份路径不同，其余逻辑一致。

### 主要特点

- ✅ 自动备份所有数据库（`--all-databases`）
- ✅ 可配置备份路径和保留数量
- ✅ 自动清理旧备份文件
- ✅ 完整的错误日志记录
- ✅ 支持定时任务自动执行
- ✅ **密码不内嵌**：强制环境变量传入，符合项目凭据治理（见 `memory/constitution.md` Security 段）

---

## 二、功能特性

### 2.1 核心功能

1. **全库备份**：`mysqldump --all-databases`，文件命名 `all_databases_YYYY-MM-DD_HHMMSS.sql`
2. **自动清理**：保留最新 N 个备份（默认 30），错误日志保留最新 10 个
3. **错误处理**：错误信息记 `.err` 日志，失败时保留供排查
4. **日志记录**：输出开始时间、文件大小、清理结果

### 2.2 配置项

- **备份路径**：`BACKUP_DIR`
- **保留数量**：`KEEP_FILES`
- **数据库连接**：`MYSQL_USER`、`MYSQL_PASSWORD`（密码强制环境变量）

## 四、安装配置

### 4.1 上传脚本到服务器

```bash
# 测试 192.168.130.41
scp docs/deploy/database_backup_to_test.sh root@192.168.130.41:/root
# 生产 192.168.130.30
scp docs/deploy/database_backup_to_prod.sh root@192.168.130.30:/root
```

### 4.2 设置脚本权限

```bash
ssh root@192.168.130.41 'chmod +x /root/database_backup_to_test.sh'
ssh root@192.168.130.30 'chmod +x /root/database_backup_to_prod.sh'
```

### 4.3 配置密码（必须）

脚本顶部已改为**不内嵌密码**：

```bash
MYSQL_USER="${MYSQL_USER:-root}"
if [ -z "${MYSQL_PASSWORD+x}" ]; then
    echo "错误: 未设置 MYSQL_PASSWORD 环境变量" >&2
    exit 1
fi
```

配置方式（任选）：

- **临时**：`export MYSQL_PASSWORD='你的密码'`（当前会话）
- **持久**：写入 `~/.bashrc`（注意 `chmod 600 ~/.bashrc`）
- **crontab**：在 crontab 行前加 `MYSQL_PASSWORD=xxx`（见第六节）
- **最安全**：用 `~/.my.cnf`（见第八节）

### 4.4 创建备份目录（可选）

脚本自动创建，也可手动：

```bash
mkdir -p /root/backups/mysql_backups/{test,prod}
```

## 六、定时任务配置

### 6.1 配置 Crontab

每天凌晨 2 点自动备份。密码通过 crontab 环境变量传入：

```bash
crontab -e

# 测试环境
MYSQL_PASSWORD=你的密码
0 2 * * * /bin/bash /root/database_backup_to_test.sh >> /root/backups/mysql_backups/test/backup.log 2>&1

# 生产环境
MYSQL_PASSWORD=你的密码
0 2 * * * /bin/bash /root/database_backup_to_prod.sh >> /root/backups/mysql_backups/prod/backup.log 2>&1
```

> ⚠️ crontab 内明文密码仍可被 root 读取。生产环境推荐用 `~/.my.cnf` 方式（第八节），crontab 不带密码。

### 6.2 Crontab 时间格式

```
* * * * * 命令
│ │ │ │ │
│ │ │ │ └── 星期几 (0-7, 0 和 7 = 周日)
│ │ │ └── 月份 (1-12)
│ │ └── 日期 (1-31)
│ └── 小时 (0-23)
└── 分钟 (0-59)
```

### 6.3 验证与日志

```bash
crontab -l                              # 查看配置
grep CRON /var/log/syslog | tail -20    # crontab 执行日志
tail -f /root/backups/mysql_backups/prod/backup.log   # 脚本输出
```

## 七、配置说明

| 配置项 | 说明 | 默认值 | 示例 |

| `BACKUP_DIR` | 备份路径 | 测试 `/root/backups/mysql_backups/test`<br>生产 `/root/backups/mysql_backups/prod` | `/data/backups` |

| `MYSQL_USER` | MySQL 用户 | `root` | `admin` |

```bash

export KEEP_FILES=20
export MYSQL_USER=admin
export MYSQL_PASSWORD=your_password
./database_backup_to_prod.sh
```

## 八、备份文件管理与安全

### 8.1 命名与保留

- 命名：`all_databases_YYYY-MM-DD_HHMMSS.sql`
- 默认保留最新 30 个，超量自动删除

### 8.2 恢复数据库

```bash
# 谨慎操作，会覆盖现有数据
mysql -u root -p < /root/backups/mysql_backups/prod/all_databases_2026-08-19_020000.sql

# 或指定库恢复
mysql -u root -p ai-devops < 备份文件.sql
```

### 8.3 安全建议（凭据治理）

本项目 constitution 规定凭据不入库。脚本已移除明文密码默认值，进一步建议：

**方式 1（推荐）：MySQL 配置文件 `~/.my.cnf`**

```bash
cat > ~/.my.cnf << EOF
[client]
user=root
password=你的密码
EOF
chmod 600 ~/.my.cnf

# 脚本里 mysqldump 去掉 -u -p 参数，改用：
# mysqldump --defaults-extra-file=~/.my.cnf --all-databases > "$BACKUP_FILE"
# crontab 无需带密码
```

**方式 2：限制脚本与备份目录权限**

```bash
chmod 700 /root/database_backup_to_*.sh
chmod 700 /root/backups/mysql_backups/{test,prod}
chmod 600 /root/backups/mysql_backups/prod/*.sql
```

**方式 3**：远程库用 SSH 隧道或 SSL 连接，定期校验备份完整性。

## 九、错误排查

### 9.1 未设置密码

```
错误: 未设置 MYSQL_PASSWORD 环境变量，出于安全考虑脚本不内嵌密码
```

**解决**：`export MYSQL_PASSWORD='你的密码'`，或在 crontab/`~/.my.cnf` 配置。

### 9.2 未找到 mysqldump

```bash
sudo apt-get install mysql-client
```

### 9.3 备份目录不可写

```bash
ls -ld /root/backups/mysql_backups/prod
chmod 755 /root/backups/mysql_backups/prod
```

### 9.4 数据库连接失败

```bash
cat /root/backups/mysql_backups/prod/all_databases_*.err | tail -20
sudo systemctl status mysql
mysql -u root -p -e "SHOW DATABASES;"   # 手动验证
```

### 9.5 备份文件为空（磁盘满）

```bash
df -h
ls -t /root/backups/mysql_backups/prod/*.sql | tail -n +31 | xargs rm -f
```

### 9.6 调试

```bash
bash -x /root/database_backup_to_prod.sh
```

## 十、常见问题

### Q1: 备份太大如何压缩？

修改 mysqldump 命令加管道：

```bash
mysqldump ... --all-databases | gzip > "${BACKUP_FILE}.gz"
```

### Q2: 如何备份到远程？

```bash
rsync -avz /root/backups/mysql_backups/prod/ user@remote:/backup/mysql/prod/
```

### Q3: 定时任务不执行？

```bash
sudo systemctl status cron
crontab -l
grep CRON /var/log/syslog | tail -20
```

### Q4: 只备份特定库？

```bash
mysqldump -u "$MYSQL_USER" -p"$MYSQL_PASSWORD" ai-devops > "$BACKUP_FILE"
```

### Q5: 备份太慢？

```bash
mysqldump --single-transaction --quick --lock-tables=false --all-databases > "$BACKUP_FILE"
```
